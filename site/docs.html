Haku kernel documentation

What the kernel does, how it is built, and where the edges are.

The documents describe the implemented subset only. A capability that has no boot-log marker is not claimed as done, and every page names the limits of the subsystem it covers — the cache size, the missing call, the port that does not have it yet.

03

Kernel ABI and development conventions

A handful of rules run through both ports. They explain most of the code that looks unusual at first read, and they are what the test markers assert.

Errors
Every syscall returns a negative errno value in the result register — never -1 plus a global. ENOSYS means exactly that the call is not implemented on this port.
User pointers
Pointers are validated page by page and copied in page-sized chunks, never dereferenced first. The validation and the copy happen once per page, not once per byte.
Markers
Observable behaviour gets a boot-log marker, and the headless runner asserts it. A change without a marker is a change nobody can verify.
Both ports
A capability lands on x86-64 and i386, or it is documented as absent from one. Drift is a bug, not a release note.
No hosted code
The kernel links no C runtime and calls no firmware service after boot. The boot loader is the only code that trusts the BIOS.
